# Перевірка пояснень у новому дизайні

Фронтенд: `feat/hexagon-explanations-updated-ui` від актуального `origin/main`.
Бекенд: `feat/rule-based-category-explanations`.
Старий stash залишається резервною копією: застосовувати його цілком не потрібно.

## Запуск

Перший термінал:

```powershell
cd G:\overtake\okil\backend-okil-project
python -m uvicorn main:app --reload --host 127.0.0.1 --port 8000
```

У бекенд `.env` потрібні робочий `DB_URL` та
`CORS_ORIGINS=["http://localhost:5173","http://127.0.0.1:5173"]`.
Використовуйте Python-середовище зі встановленими залежностями бекенду.

Другий термінал:

```powershell
cd G:\overtake\okil\frontend-okil-project
npm install --package-lock=false
npm run dev -- --host localhost --port 5173 --strictPort
```

У фронтенд `.env` задайте `VITE_BACKEND_URL=http://127.0.0.1:8000` і робочий
`VITE_MAPBOX_TOKEN`. Підтримка старого `VITE_API_URL` збережена.
Після зміни `.env` перезапустіть Vite. DB_URL на фронтенд не переноситься.

## Ручна перевірка

1. Відкрийте http://localhost:5173 і DevTools → Network → фільтр `hexagons`.
2. Натисніть гексагон у Львові. Має прийти `GET /hexagons/{id}` із кодом 200.
3. У картці вибраної ділянки натисніть «Докладніше про оцінку»: новий дизайн
   розгорне карту. Відкрийте категорію. Текст має дорівнювати полю
   `categories[].explanation` у відповіді запиту. Запиту `/explanations` немає.
4. Перевірте підпис «Відстані по прямій від центру гексагону».
5. У пріоритетах змініть вагу й натисніть «Застосувати». Список карти та деталі
   повинні використовувати однакові `weight_*`. Бал категорії та текст пояснення
   не залежать від користувацької ваги; змінюється загальна оцінка.
6. Вимкніть необов’язкову категорію, застосуйте. Для неї `enabled=false`,
   панель зберігає пояснення та показує «Не враховується в загальній оцінці».
7. Швидко виберіть інший гексагон. Запит попереднього вибору скасовується,
   пояснення не має перемикатися назад на попередню ділянку.
8. Виберіть ділянку без запису в БД: 404 пояснюється окремим повідомленням.
   Кнопка «Спробувати знову» залишається частиною нового дизайну.
9. Якщо `explanation=null` або рядок порожній, показується повідомлення про
   відсутність даних, а не вигаданий опис. Перевірте це в автоматичних тестах.

У режимі розробки StrictMode може створювати скасовані повторні запити.
Перевіряйте завершені відповіді й відсутність окремого маршруту `/explanations`.
Для CORS-помилок звіряйте точний origin браузера з налаштуванням бекенду.

## Автоматичні перевірки

```powershell
npm run test -- --run
npm run build
```

Новий `hexagonAssessment.test.ts` перевіряє єдиний запит деталей, поле
`explanation`, передачу сигналу скасування, однакові ваги в списку й деталях,
404 та запасний текст. Наявні тести ваг і API-конфігурації з нового main збережено.

Залишено всі нові стилі, геокодування, анімації, панелі зупинок і роботу з
маршрутами. Старі `MapboxMap`, `CharacCard`, `TogglerCard`, CSS і конфігурація
залежностей зі stash не переносилися: потрібні можливості вже є в main.
